## Database (PostgreSQL on Neon)

The app uses **PostgreSQL** (13 or newer; CI runs 16) through [Drizzle ORM](https://orm.drizzle.team) and the `pg` driver. Staging and production run on [Neon](https://neon.tech).

- Schema: `src/server/db/schema.ts`
- Migrations: `drizzle/` (generated by drizzle-kit, plus a custom migration that adds the `updated_at` triggers)
- Client: `src/server/db/index.ts`; pool settings in `src/server/db/connection.ts`
- Health check: `GET /api/health` answers `{"status":"ok","database":"up"}`, or 503 when the database is unreachable

Local setup:

1. Create a database, e.g. `createdb agtci`.
2. Copy `.env.example` to `.env` and set `DATABASE_URL` (e.g. `postgres://user:password@127.0.0.1:5432/agtci`) and `AUTH_SECRET`.
3. Apply migrations: `npm run db:migrate`.

After changing `schema.ts`, run `npm run db:generate` to create a new migration, review the SQL, and commit it.

### Environment variables

| Variable | Required | Purpose |
|---|---|---|
| `DATABASE_URL` | yes | The connection string the app uses at runtime. On Neon, the **pooled** one. |
| `DATABASE_URL_UNPOOLED` | on Neon | The **direct** connection string, for `npm run db:migrate` and drizzle-kit. Falls back to `DATABASE_URL` when unset, so a local database or CI needs only one variable. |
| `AUTH_SECRET` | yes | Auth.js secret (`npx auth secret`). |
| `AUTH_URL` | no | Public base URL of the site. |
| `WHATSAPP_NUMBER` | no | WhatsApp click-to-chat number, digits only with country code. |

### Neon

agtci.com is a separate site from bkesari.com, but its database lives in the same Neon project: its own database `agtci`, owned by its own role `agtci_app`, on every Neon branch. The role is a member of `neon_superuser`, so it can run the migrations without a superuser.

| Neon branch | Site | Git branch |
|---|---|---|
| `production` | agtci.com | `main` |
| `test` | the staging subdomain | `staging` |
| `dev` | development, when not using a local PostgreSQL | feature branches |

Get the URLs from the Neon console: select the branch, then **Connect**, database `agtci`, role `agtci_app`. With **Connection pooling** on, the string (host contains `-pooler`) goes in `DATABASE_URL`; with it off, the direct string goes in `DATABASE_URL_UNPOOLED`. Keep the `?sslmode=require&channel_binding=require` they end with: TLS is mandatory and the certificate is verified. Each tier's server `.env` holds only that tier's two URLs.

Why two: the pooler (PgBouncer in transaction mode) is for the app's short queries; migrations and anything that needs a session of its own (advisory locks, `LISTEN`, session `SET`) use the direct endpoint. Neon suspends an idle compute and closes its connections; the pool logs that and reconnects on the next query, and its connect timeout (15 s) leaves room for the compute to wake up. `pg` 8 prints a one-time warning that `sslmode=require` is treated as `verify-full`; that is the behaviour we want.

CI never connects to Neon: it runs its own PostgreSQL 16 service.

## Branches and promotion

| Branch | Environment |
|---|---|
| `staging` | A separate staging subdomain with its own database |
| `main` | The production site |

Work happens on feature branches. Open a PR into `staging`; CI (`.github/workflows/ci.yml`) must pass before merging. Test on staging, then promote with a PR from `staging` into `main`. Don't commit directly to `staging` or `main`.
