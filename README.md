## Database

The app uses **PostgreSQL** (CI runs against PostgreSQL 16) through Drizzle ORM and the `pg` (node-postgres) driver.

- Schema: `src/server/db/schema.ts`. Migrations: `drizzle/`, generated by drizzle-kit.
- Set `DATABASE_URL` (and `AUTH_SECRET`) in `.env`, e.g. `DATABASE_URL=postgres://USER:PASSWORD@HOST:5432/DBNAME`.
- Apply migrations: `npm run db:migrate`.
- After changing the schema: `npm run db:generate`, review the generated SQL, commit it. Don't hand-write migrations; CI fails if the schema and the committed migrations drift apart.

**Hosting note:** Hostinger *shared* web hosting only offers MySQL/MariaDB, which this app does not support. Production and staging each need their own PostgreSQL database (for example on a VPS or a managed PostgreSQL service); point each environment's `DATABASE_URL` at it.

## Branches and promotion

| Branch | Environment |
|---|---|
| `staging` | A separate staging subdomain with its own database |
| `main` | The production site |

Work happens on feature branches. Open a PR into `staging`; CI (`.github/workflows/ci.yml`) must pass before merging. Test on staging, then promote with a PR from `staging` into `main`. Don't commit directly to `staging` or `main`.
